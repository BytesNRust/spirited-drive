# Working on the game's own cars and tracks: from the CD's files to the game repo

How the owner edits the 20 original cars and 16 original tracks in Studio and gets the result into the game repo, as it works now. Detail of each window is in `track-editor.md` and `track-light.md`.

## What you have
- A **workspace** (File > Settings... > Workspace, or the row on the main menu): `<workspace>/tweaks/<id>/` for each tweak (`cy1-tweak`, `wagon-tweak`), and in it `studio/project/`, the working copy of that original (its model, textures, PSDs and masks, or the track's light folder and mask PSDs), which only Studio reads: Apply, Check and Pack zip read the `data/` mirror beside it, and a zip never holds `studio/`. `cars/` and `tracks/` are for your own car and track mods; **Open car mod** and **Open track mod** refuse a game original and say Edit tweak. An older workspace that kept the working copy in `cars/<kit>` or `tracks/<TRACK>` is converted one original at a time: opening its tweak copies that folder (with the PSDs you edited) into `studio/project/` once, the status line says how many files, and the old folder is left as it was for you to delete by hand (nothing is converted in bulk, and a second opening never copies again). Nothing in it is overwritten by Studio unless a step below says so.
- The **game repo**, told to Studio once: File > **Settings...** (Game, Workspace and Game repo, each with Choose...; the repo or its `data/`; kept in the workspace's `workspace.txt`). **Apply to game repo** asks for it the first time. That one folder is the game's `data/` for Studio: opening a track copies its light file from it, the Track light window starts from its `track_light/`, and Apply writes into it. No `--port-data` or `--light-dir` is needed (they still work for one run; the folder chosen in Settings wins over `--port-data`). For a car the repo also needs `core/formats/car_paint.c` beside `data/` (the colours are written there). Until it is set, Apply asks for it; if the folder is gone Open a track says «the game's data/ is not found (File > Settings...)».
- The owner's PSDs (`--art-dir`, read only; Studio copies them, never moves or writes them).
- A path given to Studio may start with `~` or `$HOME` (command line options, the repo and PSD folders, the Model's backdrop path).

## 1. Open an original (Edit tweak)
- **Door:** the main menu has three doors, **Edit car mod**, **Edit track mod** and **Edit tweak**. Edit tweak... lists the game's own cars and tracks (tabs **Car** and **Track**; Name, Kind, Tweak, What changed). Select a row and press **Open**: the first time it makes the project and the tweak folder, and it opens the car or the track with its panels; a row the game's files do not allow is grey, with the reason as its tooltip.
- **Cars:** Open makes the kit of one car (card, `art-source/`, `art-generated/car_masks`, `art-generated/dash_masks` for the cars you drive) in `<workspace>/cars/`. Headless: `--export-car <FOLDER> --into <workspace>/cars --cd <CD> --port-data <data>`.
- **Tracks:** Open puts the track in `<workspace>/tracks/` (it needs the workspace and the game's `data/`; the PSDs come from `--art-dir`; headless: `--steps add-originals`, or `tweak-open-row:<TRACK>` for one): `original.ini`, `light/track_light/<TRACK>.txt` (the one light file, copied from `data/`), `art-source/masks/` (the PSDs, backups with a second dot skipped) and `art-generated/track_masks/`. Open it again later: what is there stays as it was, a file that is missing is added. On a workspace made before the one-file light format it copies the one file and **takes the old light files away** (`light/track/<TRACK>.txt`, `light/track_light/<TRACK>{A,B,C,N}.txt`): nothing reads them.
- **The tweak:** `<workspace>/tweaks/<id>/` holds what differs from the game, in the game's own paths (`car_masks/`, `dash_masks/`, `track_light/`, `track_masks/`, a `mod.ini` of type tweak; Studio's own files, the PSDs, the colors and the base, are in `studio/`, which the game never reads). Opening one makes it, and makes it again when its masks change. The **Tweak** panel shows the folder (**Show folder**), what it holds against the game (same, changed or new), **Check** (makes it again from the project and looks for what is wrong, no game needed) and **Apply to game repo...**.

## 2. Edit
- **Track light:** an original track (Edit tweak > Track > Open) opens the Track light window on the track's own `light/` folder; every edit is saved into `light/track_light/<TRACK>.txt` (Save is active with unsaved changes; Revert goes back). Per moment (Dawn, Day, Dusk, Night) it sets the Sun (Direction, Height, Shadow strength; a part left unticked is the generator's own value) and the Tunnels table, where **Lamps %** at 0 makes that tunnel unlit at that moment (the car in it keeps one light on every node, no flicker) and any other value (default 100) keeps its lamps. Test drive and the photo show the working copy. The Tweak panel's **Apply to game repo...** sends the saved light file (save first; it asks for the repo folder the first time). The file format is in `track-light.md`.
- **Track masks:** paint the PSD in `art-source/masks/`; the PNGs the game reads are made when the track opens and when the PSD is saved. A PNG changed by hand is kept (state *edited by hand*) until you press **Update masks from PSD** at the top of the Track masks window (all of them) or select its row and press **Update this mask from its PSD** (that one), and answer *Replace* in the question (*Keep* leaves it, *Cancel* does nothing): the same three answers as a car's. The window also has **Show PSD folder**, **Show masks folder**, **Re-scan** and the list of changes against the game repo, as a car's Masks tab does. A texture with no PSD gets one with **Create PSD** (the button beside its name in the Track masks window, one texture at a time): the texture on a locked layer and an empty `mask` layer over it, written by Studio itself (nothing to install), never over a PSD that is there; the row then reads *no mask painted in the PSD* until you paint the `mask` layer.
- **Car masks and dash:** edit the PSDs of the kit (`art-source/`) and press **Update masks from PSD** in the car's Masks window: it reads the PSDs newer than their PNG and writes the PNGs in `art-generated/` (the PSDs are never written); a PNG edited by hand is asked about first (Replace / Keep / Cancel). **Update + dash photo** does the same and then takes the cockpit photo at night; **Show PSD folder** opens `art-source/masks`. The PNGs in `art-generated/` are made from them. Colours: the kit card's `paints=` line.
- **Traffic and police cars** (the 11 traffic cars and the police Mustang): their Car panel shows the masks only. The game uses just their masks, so there is no card, Physics from, Colors or showcase photos there; the status says «opened: edit the masks; Apply to game repo sends them…», and Check (its tooltip says what it looks for) and Apply to game repo (Tweak panel) stay. In Drive, Test drive and In-game photo run only on the City, Coastal and Alpine stages: on a circuit or an installed track they are grey and the panel says why. Apply writes their `car_masks/<folder>` like any car, and no colours.

## 3. Apply to game repo
The Tweak panel's **Apply to game repo...** (cars and tracks) lists what would change in `data/` (each file marked same, changed or new) and, on **Apply**, writes only that:
- Tracks: `track_light/<TRACK>.txt` (by lines), `track_masks/<TRACK>/*.png` (by texels).
- Cars: `car_masks/<folder>` and, for the cars you drive, `dash_masks/<folder>`, compared **by picture** (a PNG saved with other bytes but the same texels is not a change); the colours go into `core/formats/car_paint.c`. A card with more colours than the game's table holds (up to 8) is not refused: the colours are left alone and the window says so.
- A file the repo has changed by itself (neither the game's it was made from nor the tweak's) is listed apart: **Replace** writes the tweak's over it, **Skip** leaves it and applies the rest, **Cancel** does nothing. Apply is all or nothing: if a write fails, what was written is put back.
- It never commits or pushes. Review the diff in the repo and commit as usual. Asked again, it says there is nothing left to write.
