# Working on the game's own cars and tracks: from the CD's files to the game repo

How the owner edits the 20 original cars and 16 original tracks in Studio and gets the result into the game repo, as it works now. Detail of each window is in `track-editor.md` and `track-light.md`.

## What you have
- A **workspace** (File > Workspace): `<workspace>/cars/<kit>/` for each original car, `<workspace>/tracks/<TRACK>/` for each original track. Nothing in it is overwritten by Studio unless a step below says so.
- The **game repo**, told to Studio once: File > **Game repo folder...** (the repo or its `data/`; kept in the workspace's `workspace.txt`). That one folder is the game's `data/` for Studio: Add originals copies the light files from it, the Track light window starts from its `track_light/`, and Copy to game repo writes into it. No `--port-data` or `--light-dir` is needed (they still work for one run; the folder chosen in the menu wins over `--port-data`). For a car the repo also needs `core/formats/car_paint.c` beside `data/` (the colours are written there). Until it is set, Add originals and Open original track are grey and their tooltip says «Choose File > Game repo folder... first»; if the folder is gone it says «Game data folder not found: <path>».
- The owner's PSDs (`--art-dir`, read only; Studio copies them, never moves or writes them).
- A path given to Studio may start with `~` or `$HOME` (command line options, the repo and PSD folders, the Model's backdrop path).

## 1. Put the originals in the workspace (once)
- **Cars:** File > **Export original car** makes the kit of one car (card, `art-source/`, `art-generated/car_masks`, `art-generated/dash_masks` for the cars you drive). Headless: `--export-car <FOLDER> --into <workspace>/cars --cd <CD> --port-data <data>`.
- **Tracks:** the **Add originals** button (main menu, Tracks column; also in File > Open original track...) puts the 16 in `<workspace>/tracks/` (it needs the workspace and the game repo folder; the PSDs come from `--art-dir`; headless: `--steps add-originals`): `original.ini`, `light/track_light/<TRACK>.txt` (the one light file, copied from `data/`), `art-source/masks/` (the PSDs, backups with a second dot skipped) and `art-generated/track_masks/`. Press it again later (it reads **Update originals** in the Open window once the tracks are there): what is there stays as it was, a file that is missing is added. The status line says what happened: «original tracks: 16 in the workspace; N light files copied, 0 mask PSDs copied: no PSD folder (--art-dir); the workspace's own PSDs are kept» (or «the workspace has none yet», or «none new in <folder>»); with no repo folder, or a missing one, it says so and points to File > Game repo folder... On a workspace made before the one-file light format it copies the one file and **takes the old light files away** (`light/track/<TRACK>.txt`, `light/track_light/<TRACK>{A,B,C,N}.txt`): nothing reads them.

## 2. Edit
- **Track light:** File > Open original track... opens the Track light window on the track's own `light/` folder; every edit is saved into `light/track_light/<TRACK>.txt` (Save is active with unsaved changes; Revert goes back). Per moment (Dawn, Day, Dusk, Night) it sets the Sun (Direction, Height, Shadow strength; a part left unticked is the generator's own value) and the Tunnels table, where **Lamps %** at 0 makes that tunnel unlit at that moment (the car in it keeps one light on every node, no flicker) and any other value (default 100) keeps its lamps. Test drive and the photo show the working copy. The window has its own **Copy to game repo** button beside Save: the same question as File > Copy (grey, with a tooltip, when the repo folder is missing; save first, it copies the saved file). The file format is in `track-light.md`.
- **Track masks:** paint the PSD in `art-source/masks/`; the PNGs the game reads are made when the track opens and when the PSD is saved. A PNG changed by hand is kept (state *edited by hand*) until you select its row in the Track masks window, press **Update this mask from its PSD** and answer *Replace* in its question «Replace the edited mask?» (*Keep* leaves it, *Cancel* does nothing): the same three answers as a car's.
- **Car masks and dash:** edit the PSDs of the kit (`art-source/`) and press **Update masks from PSD** in the car's Masks window: it reads the PSDs newer than their PNG and writes the PNGs in `art-generated/` (the PSDs are never written); a PNG edited by hand is asked about first (Replace / Keep / Cancel). **Update + dash photo** does the same and then takes the cockpit photo at night; **Show PSD folder** opens `art-source/masks`. The PNGs in `art-generated/` are made from them. Colours: the kit card's `paints=` line.
- **Traffic and police cars** (the 11 traffic cars and the police Mustang): their Car panel shows the masks only. The game uses just their masks, so there is no card, Physics from, Colors or showcase photos there; the status says «opened: edit the masks; Copy to game repo sends them…», and Check (its tooltip says what it looks for) and Copy to game repo stay. In Drive, Test drive and In-game photo run only on the City, Coastal and Alpine stages: on a circuit or an installed track they are grey and the panel says why. Copy writes their `car_masks/<folder>` like any car, and no colours.

## 3. Copy to game repo
File > **Copy to game repo** (cars and tracks) lists what would change in `data/` and then copies only that:
- Tracks: `track_light/<TRACK>.txt` (by lines), `track_masks/<TRACK>/*.png` (by texels).
- Cars: `car_masks/<folder>` and, for the cars you drive, `dash_masks/<folder>`, compared **by picture** (a PNG saved with other bytes but the same texels is not a change); the colours go into `core/formats/car_paint.c`. A card with more colours than the game's table holds (up to 8) is not refused: the colours are left alone and the window says so.
- It never commits or pushes. Review the diff in the repo and commit as usual. Asked again, it says there is nothing left to copy.

## Checks
`editor_copy_originals` (all 20 cars and 16 tracks through Copy in a clean temp workspace), `editor_original_track_flow_a` and `_b` (tracks, including an old-format workspace), `editor_original_psd_newer` (a newer PSD, the Replace / Keep / Cancel question), `editor_e2e_car` (the 911 and LDiabl dash Copy). They need the CD's `original/` and skip without it.
