# Track light files and the light editor

In Restomod '26 the light map of a track with no PS1 disc comes from two kinds of text file:

* `data/track/<TRACK>.txt`, the track's **places**: the physical facts, the same at every time of day (its tunnels, its canyon, where the car keeps one dim tone);
* `data/track_light/<TRACK><A|B|C|N>.txt` (A dawn, B day, C dusk, N night), the **light** of that time: the rows, the tunnels' look, the tones.

If something does not fit, it is changed in the file. The files are generated by `tools/export_track_light.sh` with Restomod '26's settings and no disc; the PS1 disc's own light is never written (it is EA's and Sony's data).

## Which light the game uses

* **Restomod '26 with a file** (`<mod>/track_light/<file>`, else `data/track_light/<file>`, and the places `<mod>/track/<TRACK>.txt`, else `data/track/<TRACK>.txt`): the file is used whole, every line, always. The port's settings that change how the light is made in code
  (`made_tunnels`, `canyon_shade`, `lamp_pool_tint`, ...) count for nothing here: what holds is the file. The canyon's and the tunnels' car shade follow the file's `canyon` / `tunnel` lines
  even with `canyon_shade` / `car_tunnel_light` off in the player's settings.
  (A track with no places file has no tunnel, canyon or car_dim nodes; the log says so.)
* **Restomod '26 with no file**: the light is made in code, as before.
* **Stock '96 and Restored '96**: the files are not read at all; the light is made in code as before (their goldens do not move).
* The header's `flags` is a record, "made with these settings". When it is not the settings now, the log gets one line (`track light: <file> was made with other settings (...)`) and the
  light editor a small line under the first one. It never changes which light is used.
* What the file does not hold, the settings still decide: the night lift, the lamp pools' brightness (`lamp_pool_bright`, `city_lift 3`), the headlight beam. Those are not the made light's map.
* `TNFS_TRACK_LIGHT_FILE=0` ignores the files (the code's light only); `TNFS_EXPORT_TRACK_LIGHT=<dir>` writes the code's light as files.
* A mod can replace a file: with `--mods <dir>` the lookup tries `<dir>/track_light/<file>` first.

The file a race reads is `<TRACK><letter>.txt`, the letter by the time of day (drive_light.c; checked in the log's "cannot read" lines for dawn, day and dusk, and in the code for night):

| time of day | file (TR2 as the example) |
|-------------|---------------------------|
| dawn        | `TR2A.txt` |
| day         | `TR2B.txt` |
| dusk        | `TR2C.txt` |
| night       | `TR2N.txt` (the night has its own file: the CD's C is the dusk) |

The light editor's header shows the track and letter (`LIGHT EDIT  TR2B  node ...`), then the light file in use (`track light: file <path>`) and the places file (`places: <path>`).

## Format (a line a run of nodes, `#` starts a comment)

The **places file** `data/track/CY1.txt`:

    # tnfs track places 1
    track CY1                the header: the file is for this track
    present tunnel           the array is there even if it is empty (the rows decide a tunnel without one)
    tunnel 1064 1171         the road's tunnels, and the halls (a hall is a tunnel with a lot of light, see below)
    canyon 547 585           open air between walls (TR6's, Alpine's): the car is shaded there, the weather is not
    car_dim 322 546          the car keeps one dim tone there

The **light file** `data/track_light/CY1N.txt` (the new keys are in the second block):

    track CY1 time N nodes 1920 flags dff     the header (flags: the settings the generated rows were made with, a record)
    rows 0 5 255 255 61 61 62 63 255 60 61 62 63    nodes 0..5 have this row of 11 points
    lamp 13 100            a street lamp at node 13 (the export writes one for each of the CD's lamps; the pools are the lamps now)
    brightness 120 180 70                     nodes 120..180 at 70 percent of their light
    lamp 130 150 ff2000:80 8           a street lamp by hand: node, light in percent, an optional colour RRGGBB[:strength], an optional radius in nodes (5)
    car_tone ff8020:60                  the car's tone: a colour in hex and its intensity 0..100, the whole track
    car_tone 120 180 ff8020:60          the same for nodes 120..180 only (a later line goes over an earlier one)
    tone 120 180 ffe080:50              scene tone: nodes 120..180 are seen through a colour (hex) at 0..100 strength (yellower or whiter tunnels)
    tone 120 180 p6 p7 ff2020:60        only the row points p6 p7 (p0..p10): a side strip, e.g. beside a neon

    tunnel_tone 104.4 ff5a0d            the tunnels' look at this time: their light and their colour
    tunnel_tone 115                     a light with no colour
    tunnel 1064 1171 104.4 ff5a0d       a zone with its own look (it adds to the places' tunnels if it is not there); what it leaves out is the tunnel_tone's
    tunnel 1 62 lit                     a hall: these nodes are lit by their own lamps (see below)

**The tunnels' look.** `tunnel_tone <light> [colour]` is the look of every tunnel at this time of day. The light is a percent of full light and **absolute**: 100 is full light (a row's 255) at any time of day,
so a tunnel at 100 looks the same by day and by night, more than 100 is brighter. The colour is `RRGGBB` in hex, with an optional `:strength` (0..100, 100 whole: the colour is the tint it gives the dim levels, as a `tone`'s);
the export also writes a colour as `r/g/b`, the three factors 0..1 (`1/0.68/0.28`), where 8 bits do not hold a made look exactly; you can write either. A light is a number (`104.4`), a colour a token of 6 hex digits or `r/g/b`.
With no `tunnel_tone` a tunnel is dark: 10 % of full light and no colour.

**A look a zone.** `tunnel_tone` is the time's default look; a `tunnel a b <light> <colour>` zone line gives those nodes a look of their own (a light, a colour or both; what it leaves out is the `tunnel_tone`'s). A zone whose look is the
default's is nothing special; each different look takes one of the 16 **tone slots**, shared with the `tone` lines (a 17th, of either, is a bad line, and zones with the same look share a slot). A node has one slot: a `tone` line over a zone's nodes
replaces the zone's look there. The world's tunnel polygons of a zone are tabled by its look (the lamps hanging in tunnels, and the lamp flares, keep the default's). The light editor shows `tunnel look: light 104.4%  colour ff5a0d` for the node's own
(`this zone's own` when it is a zone's, `a hall: lit by its lamps` for a hall).

**The car in a tunnel** takes its zone's light and colour in every tunnel: its colours are multiplied by `light / 100 x colour` per channel, above full light too (a `tunnel_tone 215` lights the car 2.15 times as much as a 100 one, as it lights the walls and the road); the excess over 1 comes in with the road's darkening inside the tunnel (the rows' road at 100 of 255), so the open road before a mouth is not brightened, and at 100 and white nothing is different. Under a lamp (even nodes) that is the full look, between two lamps (odd nodes) 40 % of it
(`LIGHT_SYNTH_LAMP_GAP_PERCENT`), and it comes in over the 6 nodes outside the mouth (the weather's mouth). A hall keeps the lamps of its own, `car_dim` the one dim tone. There is nothing else to set: `car_disc`, which gave the car the
CD's own ratios, is gone (a bad line, and the export does not write it).

**Places and times.** The places are loaded first, then the time's file: a `tunnel` line in a time file adds to the places' tunnels (the union), it never takes one away. A zone with `lit` is a **hall**: a tunnel with a lot of light,
lit by its own lamps (TR7's steelworks, `tunnel 1 62 lit`); it keeps the terrain's light and the lamps' alternation on the car, and has no light or colour of its own. The places file lists a hall as a tunnel; the time's file says it is lit.
Under all of it are the file's `rows`, the owner's retouches (`brightness`, `tone`, `car_tone`, `pool`) over the made light, so a row he writes is the row.

What the old format had and this one does not read (a bad line, like any word the format does not know): `hall`, `cast neutral city`, `car_disc`, and `tunnel_tone day|night r g b percent`. `tunnel`, `canyon` and `car_dim` are the places file's:
in a time file only `tunnel` (the zone line above) is read.

`car_tone` takes each of the car's colours toward the tone at its own brightness, and shows the nearest colour the palette has, of any hue: a red car goes toward orange,
a white one to orange, a dark blue one stays bluish where the palette has no dark orange near. (The tunnel's own look, a zone's light and colour, only changes the car's brightness and tint by the ratio above.)

The words are English. The format's first version was Spanish (`pista hora nodos banderas filas presente tunel coche_tenue canon coche_disco tono_tunel brillo tono_coche`):
the port still reads those words as the English ones, and the export writes English only.

The generated lines (`rows`, `lamp`, `tunnel ... lit`, `tunnel_tone`, and the places file) are what the export writes; a zone's own look is written as `tunnel a b <light> <colour>`.
`tone` tints the road, walls and scenery of those nodes (the tint is 1 + (colour/255 - 1) x strength, applied to the lit colours; in a tunnel, over its cast). A track has at most 16 distinct tones (a 17th is a bad line); each is built the first time it is seen (about 2.5 ms and 4 KB). A later line over the same nodes replaces the earlier. A polygon takes a tone only when all four corners have it, so a strip follows the row points. The light editor shows the current stretch's tone.

## The street lamp

    lamp <node> <light%> [RRGGBB[:strength]] [radius in nodes]        (Spanish: `farola`)

A lamp is light, added where it stands. It lights the road, the walls beside it and the car. The old `pool` and `car_pool` lines are gone (a line with them is a bad line); the export writes
`lamp <node> 100` for each of the CD's street lamps. Under the lamp its light is full, and it fades smoothly to nothing at the radius, with no step at a node's edge: the fall is
`(1 - distance / reach)^2`, where distance is measured in metres from the lamp's world place, the post's own (the scenery of the lamp boards at that node) or, if the line matches no post, the
node's centre.

* **Light** is a percent, 1..1000: the strength. 100 is the lamp the export writes, a clearly visible pool of warm light under it at night. More is brighter, never wider (the radius sets the size).
* **Colour** is optional, `RRGGBB` and an optional `:strength` 0..100 (as in `tone`), default 100. With none the lamp is the warm street lamp's colour. A colour is added as light (it brightens and
  tints, keeps the surface's own detail and never darkens anything), the warm colour of the lamp mixed toward it by the strength: `ff2000:50` is half way.
* **Radius** is optional, in nodes, 1..64; the default is 5 (about 30 m on CY1). It is the pool's size.
* How it is drawn: when the track loads each lamp lifts every row point (the 11 points of each node) within its reach by its strength times the falloff at that point's own place in the world, and
  the night's floor under it too, so the polygons' light, which the renderer interpolates between corners, is the pool, at no cost a frame. The warm or coloured light is added by the polygons
  near a lamp: a table of the lamp's colour graded per pixel between the lit tables and these by the lamps' light at each corner. The car takes the lamps' colour added to its light by its own
  distance to each lamp (up to the old pool's ceiling).
* The lamp list replaces the old pools: with `lamp` lines the pool classes the code makes (road tint, car light, the pools' floor) are dropped, the lamp is all of it.
* A track has at most 2048 lamps; a line past that is a bad line.
* The lamps are for the night: in the dawn, day and dusk files (`...A.txt`, `...B.txt`, `...C.txt`) `lamp` lines do nothing (the editor says `lamp: off (dawn/day/dusk)`) and the export writes
  lamps only in the night's.
* The lines are read only with the port's `track_light_lamp` (`TNFS_TRACK_LIGHT_LAMP=0/1`; on in Restomod '26, off in Stock and Restored, which do not read the files at all). The log says
  `lamps: N placed` and `lamps: baked into M row points`; `TNFS_LAMP_BAKE=0` leaves the rows alone (the colour and the car's light stay), for comparing.
* The light editor's line shows the nearest lamp of the node the car is at: `street lamp: node 125, light 100% (colour 1.00 0.90 0.55), reach 30 m`, `none`, or `lamp: off (dawn/day/dusk)`.
* Not lit by the lamps yet: the scenery objects (buildings, trees, posts: they are lit as a whole by their node) and the road beyond the camera's near detail (the far, flat polygons).

## The tunnels' own lamps (`tunnel_lamps`)

At night, with `tunnel_lamps` (on in Restomod '26; `TNFS_TUNNEL_LAMPS=0/1`), the lamps hanging in a tunnel or a cavern light the walls and the road in a pool under each, as the street lamps do outdoors. Which polygons are lamps
is the **yellow** of the track's slot masks (`data/track_masks/<TRACK>/slot_<NN>.png`, docs/modding.md: the lamp's texture, its place and colours come from it), and for a track whose masks have none the table of `game/race/tunnel_lamp_textures.c` (the lamp textures of CY1, CY2, CY3, TR3 and TR4): every even node whose polygons use one of them has a lamp on each side of the road that has such polygons (the lamp textures hang in the strips at the walls), at the middle of those polygons (`game/race/tunnel_lamps.c`). It is made when
the track loads; no file lists them, and a `lamp` line is not needed. The lamp is warm, 300 percent (500 saturated the tunnel by half the reach, and the pools of both sides joined into one flat band), and reaches 1.8 nodes (11 m): CY1's lamps hang in the middle of a 19 m tunnel, 6 m apart across (the lamp textures are in the lane strips), so at 1.2 nodes the walls were out of reach (the left one 7 m from its lamp, the right 5.8 m: only the right caught a sliver); at 1.8 both walls and the ceiling are lit. That reach is across the road only: along it a pool reaches 1.3 nodes (8 m), an ellipse, so with the lamps every 2 nodes (12 m) the light falls to 5 % half way to the next lamp and the tunnel alternates light and shadow (a round pool of 1.8 nodes overlapped the next one and the tunnel was one even band). The lamp texture's own colours are read again once the race's palette has remapped the track's texels (the colours under the yellow marks), so the fitting keeps its night entries and its halo (`lamp_flares`) in the Modern 3D view too.

* The pool is ADDED to the tunnel's own light, whatever `tunnel_tone` is: at 104 a tunnel is lit as before plus its pools, at 50 it is dark between the lamps and each lamp still gives its full pool. Nothing is baked into the light rows
  (the street lamps' bake lifts toward full light; the tunnel's lamps never scale or cap what the tunnel's light is).
* A tunnel polygon takes the tunnel's lamps only; the street lamps' light stays out of it. The open road at a mouth takes the tunnel lamps near it like any lamp.
* The pools are drawn on every tunnel polygon, near or far: a polygon of the road mesh is 1 to 8 nodes long, so it is drawn as cells a node long (about 4 m across), each lit by the lamps' heat at its own corners (`game/viewer/tunnel_cells.c`); a polygon with a scene `tone` or a zone's own `tunnel` look keeps its own table as the base and the lamps' pools are added over it (before, such polygons, CY1's ceiling among them, took none).
* The cars take the lamps too (with `car_tunnel_match` 1): in a tunnel with lamps the car's light has no node-parity alternation (1.0 under a lamp on even nodes, 0.75 on odd ones); it is the between-lamps level (75 percent) everywhere, and each lamp lifts it by the car's distance to it (the street lamps' car light, `track_node_light_lamp_car`), at most to full light, so the car brightens as it passes a lamp whatever the lamp's node. A car already above full light is left as it is. With `car_tunnel_match` 0 or no lamps it is the alternation as before.
* `tunnel_lamps` 1 is night only; 2 (Restomod '26's default) lights the lamps by day too (dawn, day, dusk), at the same strength over the day's tunnel light: a day tunnel is dim, so its lamps read as on. The street lamps stay night only (`track_light_lamp`). By day the lamps are 150 percent (`TUNNEL_LAMP_DAY_STRENGTH`, half the night's): at 300 the day's road turned strongly amber, brighter than at night.
* In a Restomod '26 race that has made light (a track light file or the code's); Stock '96 and Restored '96 are as before.

## The weather and the tunnels (Restomod)

A tunnel (the places' `tunnel` nodes) or a hall (`tunnel a b lit`) is a closed zone for the weather: inside it there is no rain, no fog, no rain's haze, no lens drops and no lightning, and the thunder is muffled to 40 %. All of it fades in over the 6 nodes outside a mouth
(the light editor shows `weather: open|closed N/16` for the node). Coastal's galleries, which the road marks but the files do not, count as closed zones too. A hall is a tunnel with a lot of light and has a roof (TR7's steelworks, `tunnel 1 62 lit` and `tunnel 1011 1023 lit`, and its tunnels, `tunnel 465 470`, `571 609` and `682 695`, have no rain); a `canyon` is open air (Alpine's, `canyon 600 771`, rains). Stock and Restored have no weather of their own and are not changed.

## Snow (Restomod)

A track opts in to snow with `snow 1` in its places file (`data/track/<TRACK>.txt`; Alpine 3's has it, a mod's copy of any track can). With `snow_weather` on (Restomod '26's default; `TNFS_SNOW_WEATHER=0|1`):

- the weather *rain* is snow: white flakes that fall slowly (9 to 22 percent of the view's height a second) and sway sideways, with the weather's openness (none inside a closed zone, thinned out at its mouths); the *storm* is heavier snow (three times the flakes, a wind that leans them all one way) with no lightning and no thunder. The lens has no drops. The road stays wet as in rain: the reflections, the spray behind the tyres, the wet tyre sound and the rain's grip are all `weather_wet`'s, which the snow does not change;
- the rally of the track (`variant_r`) is on snow, `RALLY_GRAVEL_SNOW` (`rally_gravel.h`): the places file's `snow_map FROM TO` lines make texture slot FROM draw with the bitmaps of slot TO (slots are `id * 3 + letter`, `TRACK_TEXTURE_SLOTS` = 144, as the segments' texture bytes have them), so the road and the shoulder are covered in the track's own snow textures and nothing new is stored. Those textures are snow with patches of grass, and the grass must not show on the road: when the track loads, every green texel of them (green by the track's own palette) is painted snow-white, into the road's own bitmap in the track's bank before the race's palette is made, so the colours are the palette's own and the snow slots the scenery uses (embankments, trees) and everything off the road are not touched (`track_art_remap_slots`). A road bitmap with no room for the snow's pixels takes the snow texture as it is. Alpine 3's are `snow_map 3 36` and `snow_map 4 37` (its road and its shoulder). A track with `snow 1` and no `snow_map` keeps its road art. The grip is `RALLY_SNOW_GRIP` 0xc0, half the rally gravel's 0x180 (packed snow's friction is about 0.3 against gravel's 0.6), and it rolls half as hard again (0xc0 against 0x80); the rain's grip factor is not put on it a second time, the number being the wet snow's. The tyres throw a white powder puff instead of dirt, and the rolling noise is the gravel's.

`tools/export_track_light.sh` writes the places from the light the port makes, which knows nothing of snow: `FORCE=1` over a file with these lines would lose them.

## Regenerating the files

When a change to the engine alters the light it generates, the files are regenerated with `tools/export_track_light.sh <bin> <original/> [data dir]`: one headless run a track and time, writing `data/track_light/<TRACK><A|B|C|N>.txt`
and `data/track/<TRACK>.txt` (the places are the same at the four times: the script says if they are not). The export writes **only the files that are missing**: an existing file is kept ("kept <file> (exists; FORCE=1 to overwrite)"), since it may hold your edits (tunnels, tones, lamps, rows). `FORCE=1 tools/export_track_light.sh ...` rewrites them all and loses those edits.
A retouch can also live in a mod's folder (`<mod>/track_light/<file>` goes first). The placing step is `tools/export_track_light_install.sh`, tested by `tests/export_keeps_edits.sh`.

## The places file decides what is closed

The closed zones (where it does not rain: the weather's looks, the spray and the lamps' mirrors, the car's grip) are the places file's `tunnel` lines (halls included; a `canyon` is open air), nothing else: Coastal's galleries are `tunnel` lines of `data/track/CL2.txt`.
The road's own roofed bits are the stand-in only for a track without a places file. When the road roofs a run the file does not close, the game logs `wet zones: <track>: the road's own roof covers N nodes the places file does not close: a..b` (verbose): the rain falls there until the file says `tunnel a b`.

## Light editor

`light_edit=1` in `port.cfg` (or `TNFS_LIGHT_EDIT=1` as a launcher) shows, in a race with a made light, the node the car is at, `track light: file <path>` or `track light: made in code (no file for ...)`,
and the values there. A small cross follows the mouse pointer, and the `aim (+)` line names the texture under it as the mask file that paints it (`road texture slot_38`, `scenery_05`): point at a lamp (F10 holds the race) and that is the file to mark yellow (see the modding guide). Only with the editor on; a race without it reads no mouse. F10 holds the race where it is, F11 copies a `brightness N N 100` line to the clipboard. Saving the light file **or the track's places file** (`data/track/<TRACK>.txt`: its `tunnel`, `canyon`, `car_dim` lines) reloads the light within a second, without leaving the race, and the dry zones with it (where the rain falls and the tyres lose grip: `wet zones: <TRACK> made again` in the log). `snow` and `snow_map` change textures when the track loads: after editing them, restart the race (the editor's message says so). Without the editor nothing is watched.
